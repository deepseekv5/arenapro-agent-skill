# Skill 设计手记

这份文档解释 arenapro-docs Skill 为什么长这样。官方文档只回答"怎么用 ArenaPro"，这里回答"怎么用这个 Skill"。

## 核心取舍：结构转化 + 字面检索，而不是 RAG

89 篇文档约 74 万字符，直接塞上下文会挤爆窗口；上向量库则需要外部服务与索引维护，对一个文档规模稳定、总量不大的场景不成比例。最终选择：

1. **一次性把 VitePress SSR 产物转成规范化 md**——保留章节层级、代码块语言标注、frontmatter 出处，让人和机器都好读；
2. **运行时用零依赖字面检索**（`search.py`）——牺牲一点召回率，换来"拷完就能用"：不需要网络、embedding、数据库，任何有 python3 的 agent 环境直接工作。

代价是近义词检索要靠人（或 agent）换词。`search.py` 无命中时会输出各关键词单独命中的文件数，就是为把这个代价变成可操作的线索。

## 上下文三层加载

对应 SKILL.md 的结构设计：

- 第 1 层：frontmatter description（常驻，只有触发词，不含内容）；
- 第 2 层：SKILL.md 正文（触发后加载，约 100 行，只有目录表和流程，不放正文）；
- 第 3 层：references/（永远按需读取，search.py 输出强制截断就是为守住这层）。

任何一环把文档全文提前带进上下文，都算这个 Skill 设计失败。

## 快照 + 刷新，而不是实时抓取

文档库是快照（`references/docs/`），因为：离线可用、结果可复现、不依赖 docs.dao3.fun 的可用性。同步靠 `scripts/refresh_docs.py`，设计上做了三个防呆：页面清单从侧边栏自动发现（不维护硬编码列表）；只写站点来源文件（`own/` 与本目录永不被覆盖）；空壳页过滤（源站存在 ex.html 这类无正文残留页，转化进来只会污染检索）。

## 文档目录的解析链

`--docs-dir` > `ARENAPRO_DOCS_DIR` > 内置 `references/docs/` > 相邻 `../../docs-md/`。排序原则：显式参数最优先，环境变量给"装了 Skill 但想跟项目库最新版"的场景留门，内置副本保证单独安装时自给自足。无效路径不静默回落，会向 stderr 提示——静默换目录是检索类工具最难查的 bug。

## 边界声明

本 Skill 是社区镜像：转换工具、索引、自写文档归本仓库；ArenaPro API 的真相归 docs.dao3.fun。文档冲突时以 `package/*/api/` 章节优先；快照过期时以官网在线版优先，并应尽快跑 refresh。
